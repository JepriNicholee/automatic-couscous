# Perbaikan dari wawancara agen (versi 2.10, versionCode 21)

| # | Temuan | Perbaikan | Lokasi |
|---|---|---|---|
| 1 | Kode alat ditulis di dalam `run_command` | Perintah yang memanggil alat seperti fungsi (`tool_api`, `self_audit(...)`, interpreter + nama alat, atau nama alat sebagai perintah) ditolak tanpa dijalankan, dengan petunjuk panggil native + tanda tangan semua alat. Deskripsi `run_command` menegaskan "hanya shell". | ToolGuidance.kt (`detectToolCodeInShell`), ToolExecution.kt, MainActivity.kt |
| 2 | Modul `tool_api` ditebak | Daftar alat eksplisit (nama, parameter, fungsi) selalu ada di prompt sistem, termasuk pernyataan bahwa `tool_api` tidak ada. Tes menjaga daftar tetap sama dengan skema alat. | `ToolDocs`, ToolGuidanceTest |
| 3 | Harapan `self_audit` dan timeout | Deskripsi alat menyebut cakupan dan batasnya (statis, bukan build, bukan checksum). Progres audit tampil live (`KITA_PROGRESS` 0/8 sampai 8/8), hasil memuat durasi, dan galat timeout/folder diberi petunjuk. Timeout tetap 900 dtk (sandbox 1800). | SelfUpgradeIntegration.kt, kita-self.sh, ToolGuidance.kt |
| 4 | Path file diisi ke parameter folder | Validasi sebelum alat jalan untuk `self_audit`, `self_upgrade`, `build_apk`, `validate_project`: path berekstensi file ditolak dengan contoh yang benar. | `folderArgProblem` |
| 5 | `hasil-uji.md` tidak konsisten | Template, penamaan `Tn judul-kebab-case`, dan aturan kolom Langkah (jumlah pemanggilan alat, termasuk yang gagal) ada di prompt, PANDUAN_ALAT.md, dan `HasilUji` (teruji). | ToolGuidance.kt |
| 6 | Galat GitHub 403 tidak jelas | `build-github.sh` memeriksa token dengan `gh api -i user` dan menjelaskan 401, 403 izin kurang, SAML, rate limit, atau jaringan (plus scope token saat ini). Polling workflow berhenti segera pada 401/403 dan tidak lagi berputar sampai timeout. Aturan Diagnosis baru untuk HTTP 401/403. | tools/build-github.sh, BuildApk.kt, Diagnosis.kt |
| 7 | Lokasi folder membingungkan | Peta path selalu ada di prompt; aturan Diagnosis untuk "No such file or directory". Bug terkait: pemeriksaan folder reference pada `create_android_project` dan `build_apk` dihitung dari home, padahal path relatif ke folder kerja ~/MYTHOS; kini memakai `absPath`. | Diagnosis.kt, ToolExecution.kt |
| 8 | Tidak ada validasi struktur sebelum build | Alat baru `validate_project` (hanya membaca): settings/build Gradle, manifest, gradlew + wrapper, workflow, applicationId, namespace, versionCode, sumber, tes, remote git, penamaan folder, folder reference, token GitHub. Keluaran: GAGAL (wajib diperbaiki) dan peringatan. | ToolGuidance.kt (`ProjectCheck`), ProjectCheckIntegration.kt |

Catatan verifikasi: `build-github.sh` diuji dengan `gh` tiruan (401, 403, rate limit, tanpa jaringan, 200); skrip `validate_project` dijalankan pada proyek ini; audit dijalankan dengan progres. Kode Kotlin dan tes unit baru (ToolGuidanceTest, tambahan DiagnosisTest) belum dikompilasi atau dijalankan di lingkungan ini (tanpa Gradle/kotlinc): jalankan `./gradlew testDebugUnitTest` atau push untuk workflow CI.
